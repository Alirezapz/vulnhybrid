VulnHybrid research upgrade: audit, experiments and limitations

Run date: 1 November 2026. Author: Alireza Pazouki.

Findings that matter

The code and experimental infrastructure are stronger, but these experiments do not demonstrate a reliable new detection improvement. On the primary commit-disjoint cohort, the validation-selected method is gated_residual: accuracy 51.16%, F1 0.6688, MCC 0.0597. An always-vulnerable classifier already reaches F1 0.6684. The selected method's F1 advantage over that trivial baseline is 0.00039, with a commit-cluster 95% interval [-0.00992, 0.00918]. This interval does not establish a positive gain.

The frozen external probe is even more diagnostic: 0.00% of 415 vulnerable/fixed pairs have both labels correct for that method. Its external ROC-AUC is 0.5044 and FPR is 100.00%. Strong recall/F1 here is mostly an operating-point artifact, not evidence of understanding the repair. No SOTA claim is justified.

What was actually executed

Downloaded all 27,318 Devign/CodeXGLUE functions and 846 C/C++ SVEN functions from pinned revisions. Evaluated 19 methods in each of four regimes (76 matched test comparisons), plus frozen transfer evaluations for every method. The prototype methods combine lightweight lexical classifiers with measured static evidence; they are not new LLM runs and not named neural-paper reproductions.

Core regressions and original end-to-end tests were run locally, including the real mock HTTP transport. Static engines and taint fixtures were executed. The taint fixture contains an explicit expected miss for an array update. No paid API, GPU, exploit generation, or real-project vulnerability discovery was used. Published-looking historical thesis tables were not treated as new measurements because their supporting full outputs are absent from the ZIP.

Data audit and leakage controls

The original data has 97 normalized duplicate groups, 91 conflicting-label groups, 23 clone groups crossing official splits, and 1902 commit IDs in multiple splits. Official-split deduplication removes token-identical clones but leaves 1891 overlapping commit groups.

The primary protocol puts entire commits in one split, then deduplicates code. It retains 22078 train, 2572 validation and 2500 test functions, with zero normalized clone or commit overlap. Of validation functions, 1254 fit models/calibrators and 1318 select thresholds and the method. These halves are also commit-disjoint. The split is randomized by stable hash, not chronological; near-clone and label-noise threats remain.

SVEN is used only for transfer, not training. Eight whole C/C++ pairs are excluded because of Devign overlap or equal normalized before/after code, leaving 415 pairs / 830 functions. This repurposes its upstream training and validation release as an external detection probe; it is not an official SVEN test leaderboard. Scores/thresholds are frozen before this evaluation.

New combinations and ablations

Held-out evidence stack: a regularized logistic combination of token, character and static logits fit on val_fit, separate from training and selection. Gated residual: anchor the mean lexical logit, then fit an intercept plus shrunken binary tool-rule corrections. Multiple warning lines do not multiply the same evidence. Intercept-only isolates base-rate recalibration; mean and log-odds fusion are established controls.

These are project-specific experimental combinations of existing statistical ideas. They are not claimed as world-first methods. On the primary cohort, the gated residual minus token-LR F1 difference is -0.00053, cluster interval [-0.00411, 0.00299]. The static evidence has not earned a demonstrated generalization improvement. The narrow explicit-source taint rule produced zero corpus alerts; negative results remain in the comparison.

McNemar tests measure accuracy differences, not F1. Their Holm-adjusted p-values are included as secondary analyses; same-commit correlation makes the clustered F1 difference intervals more appropriate for the central F1 question. Intervals are conditional on this run and exclude training/selection variance.

Engineering changes

Strict model-output validation; duplicate-verdict rejection; rule-event deduplication and stable log odds; explicit analyzer errors; matched-denominator evaluation; validation-only weight fitting; seeded sample selection; benchmark hint removal; and model/prompt/input-aware checkpoint hashes. Details and remaining limitations are in CODE_AUDIT.md. None of these fixes retroactively validates the old paper's missing experiments.

Publication assessment

This is a reproducible research artifact with useful negative evidence, not yet a submission-ready claim of a better vulnerability detector. A stronger paper needs actual named neural/modern-LLM baselines on the same cohort, chronological PrimeVul and paired testing, multiple split/training seeds, manual real-project alert verification, and a mechanism that improves those outcomes. The literature review separates reviewed work from implementations actually executed.

Reproduction and evidence

Use research/fetch_data.py, research/collect_static.py, research/benchmark.py and research/summarize.py. README contains the exact commands. The protocol and its hash were recorded before inspecting these test predictions. Data revisions, byte hashes, cohort memberships, exclusions, validation partitions, per-sample scores, structured analyzer findings, diagnostics, environment versions and comparisons are included. Underlying upstream source datasets are downloaded separately.

All four run durations (seconds): official_dedup: 162.9, commit_disjoint: 158.1, ffmpeg_to_qemu: 84.5, qemu_to_ffmpeg: 85.1. They overlapped in pairs and are not an additive wall-clock estimate. These are end-to-end CPU benchmark times, not model-only inference latency. No dollar or LLM token savings are inferred.
